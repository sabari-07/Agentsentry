AgentSentry AI

Autonomous AWS incident remediation that proves its own fixes. When a CloudWatch alarm fires anywhere in the account, AgentSentry inspects the affected resource read-only, grounds its diagnosis in current AWS documentation through the Agent Toolkit, reasons over the evidence with Claude Sonnet on Amazon Bedrock, and opens a pull request containing the actual CDK infrastructure change. A human merges, GitHub Actions deploys it, and only then does AgentSentry re-read the live metric and publish the measured number.

HOW IT WORKS

  1. Any CloudWatch alarm in the account enters the pipeline via EventBridge.
  2. The affected resource is identified from the alarm payload, across 7 namespaces.
  3. The resource is inspected with read-only calls, each one recorded for audit.
  4. Current AWS documentation is retrieved at runtime through the AWS MCP Server.
  5. A model reasons over that evidence; deterministic guards decide if it may act.
  6. The fix ships as a reviewable pull request containing real CDK code.
  7. After a human merges and CI deploys, the live metric is measured again.

WHAT MAKES IT DIFFERENT

The agent never merges and has no path to mutate infrastructure. The model selects from a fixed set of permitted actions and must name the same resource the alarm named, so it cannot author arbitrary code or redirect a fix elsewhere. And “resolved” is a measurement it has to earn: when a metric is still breaching, it withholds certification and says so publicly on the pull request.
